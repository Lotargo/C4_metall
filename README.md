# Подготовка производства

Статический сайт на Astro с презентацией проекта, техническим разбором и общими
документами плана реализации. Документы можно добавлять обычными Markdown-файлами
и редактировать прямо на сайте.

## Локальный запуск

Нужны Node.js 24.12+ и npm. Выполняйте команды из корня репозитория:

```sh
npm ci
npm run dev
```

Сайт: [localhost:4325](http://localhost:4325/).
Документы: [localhost:4325/implementation/](http://localhost:4325/implementation/).

## Как добавить Markdown-документ

1. Поместите файл в **`documents/implementation/`**. Вложенные папки тоже
   поддерживаются. Импорт в код и ручное изменение меню не нужны.
2. При необходимости задайте название и порядок через метаданные в начале файла.
   Например, `documents/implementation/20-new-stage.md`:

   ```md
   ---
   title: Этап 4. Согласование
   description: Порядок согласования результатов
   order: 20
   ---

   # Этап 4. Согласование

   ## Цель

   Текст документа.
   ```

3. Откройте `/implementation/`: документ появится в меню. Его отдельный адрес —
   `/implementation/20-new-stage/`.
4. Добавьте файл и его изображения в Git. На опубликованном сайте новый документ
   появится после сборки и публикации.

Метаданные необязательны. Название берётся из `title`, затем из первого
заголовка `#`, затем из имени файла. Порядок: `order` по возрастанию
(по умолчанию 100), затем путь файла с учётом чисел. В `/implementation/`
открывается первый документ; `##` и `###` формируют оглавление.

Все `.md` в этой папке предназначены для публикации. Черновики и внутренние
материалы храните вне `documents/implementation/`.

### Изображения, ссылки и оформление

Общие изображения и вложения кладите в `public/`, например
`public/images/flow.png`. В Markdown путь начинается от корня сайта:

```md
![Схема процесса](/images/flow.png)
[Другой документ](21-next-stage.md#цель)
```

Также поддерживаются изображения рядом с `.md`, таблицы GFM, списки с отметками,
Mermaid и формулы LaTeX. Полные примеры, вложенные папки и обновление документов —
в [руководстве по документам](documents/README.md).

## Как связаны Markdown и правки на сайте

`.md` задаёт страницу, пункт меню и начальное содержимое. Правки в редакторе
автоматически сохраняются отдельным JSON в Firebase Firestore и появляются у
других посетителей. Любой посетитель может редактировать без окна входа.

**Если в Firebase уже сохранён документ, редактор загружает его содержимое.
Замена `.md` и новая сборка не перезапишут эту облачную копию.** Автоматического
слияния с новым Markdown и экспорта правок обратно в `.md` пока нет.

Путь файла без `.md` — идентификатор документа. Переименование или перенос
создаёт другой адрес и идентификатор; прежние облачные правки автоматически
не переезжают. Поэтому существующий документ лучше обновлять под тем же именем.

При текущей конфигурации локальный сайт тоже подключён к общей базе Firebase.
Настройки и режим изолированной локальной работы описаны в
[руководстве](documents/README.md#локальная-работа).

## Разделы и файлы проекта

| Адрес | Содержание |
| --- | --- |
| `/` | Презентация процесса и ролей агентов |
| `/it/` | C4, исходники, контракты и хранение данных |
| `/implementation/` | Общие редактируемые документы |
| `/plan/` | Обзор входящих данных и этапов работ |
| `/results/` | Результаты чтения трёх чертежей |
| `/voksa/` | Разбор и сравнение с ВоксаТех |

- `documents/implementation/` — публикуемые Markdown-документы.
- `public/` — изображения и другие статические файлы.
- `src/content.config.ts` — загрузка документов и схема метаданных.
- `src/components/ImplementationDocument.astro`, `src/scripts/document-editor.ts`,
  `src/editor/` — страница, редактор и синхронизация.
- `src/data/firebase.json`, `firestore.rules` — публичная конфигурация Firebase
  и правила доступа.
- `src/data/` — данные презентации, архитектуры, результатов и ВоксаТех.
- `docs/qa/` — отчёты проверок; [DESIGN.md](DESIGN.md) — оформление.

## Проверка изменений

```sh
npm run test:editor
npm run typecheck
npm run verify:evidence
npm run build
```

`npm run preview` открывает готовую статическую сборку на
[localhost:4326](http://localhost:4326/). Проверьте новый документ, оглавление,
изображения и ссылки. Результат сборки находится в `dist/`.

## Публикация

GitHub Pages обновляется после push в `main` через
[workflow](.github/workflows/deploy-pages.yml). Он сам задаёт префикс
`/C4_metall/`. Для другого статического хостинга загружается `dist/`,
собранная с нужными `SITE_URL` и `BASE_PATH`.

Готовая обёртка для существующих Sites и GitHub Pages, из PowerShell в ветке
`main`: `npm run deploy`. Она фиксирует текущие правки коммитом и публикует
его на обе площадки. Нужны авторизованные `gh` и `codex` с подключённым Sites.
Проверка окружения без публикации: `npm run deploy -- -DryRun`.
Подробности — в [скрипте](scripts/deploy-both.ps1), проект Sites — в
[.openai/hosting.json](.openai/hosting.json).
