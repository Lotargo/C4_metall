# Общий план

Дата: 27.10.2026.

Цель: организовать полный процесс от чтения инженерного чертежа и подготовки справочных данных до выбора заготовки, построения маршрута и расчёта предварительной сметы с проверкой оператором.

План включает шесть этапов: чтение чертежа, подготовку справочников, инженерные расчёты, работу оператора, проверку качества и улучшение скорости и затрат.

## Статусы выполнения

**Общий статус: Частично. Состояние на 27.10.2026.** Основной проверенный сценарий: детали из круглых заготовок. Полный путь от чертежа до согласованной сметы ещё не завершён.

**Выполнено**: результат работает и проверен в указанном объёме. **Частично**: готова часть задачи. **Не выполнено**: требуемого результата пока нет. Технические основания и границы проверок приведены в [подробностях реализации](#implementation-details).

Определить максимальный размер сечения детали `A`: диаметр, сторону квадрата либо ширину шестигранника по вписанному диаметру. Учесть большее отклонение размера `B`:

```text
C = A + B
```

Перебрать сортамент и выбрать минимальный размер сечения заготовки `A1`, удовлетворяющий условию:

```text
C < A1 + B1 - (L + L1) × K1
```

| Обозначение | Значение |
| --- | --- |
| A | Максимальный размер сечения детали |
| B | Большее отклонение размера сечения детали |
| C | Размер сечения детали с учётом допуска |
| A1 | Номинальный размер сечения заготовки |
| B1 | Минимальное отклонение размера сечения заготовки |
| L | Длина детали |
| L1 | Большее отклонение длины детали |
| K1 | Кривизна по длине заготовки |

Правило представления `K1` и применения поправки приведено в открытых вопросах раздела 7.

<a id="p-2-6"></a>

### 2.6. Подбор трубного проката

Сначала проверить наружный размер трубы по условию из пункта 2.5.

Определить минимальный сквозной диаметр детали `D` с меньшим отклонением `F`:

```text
E = D + F
```

Для выбранного наружного размера перебрать толщины стенки `δ` по условию:

```text
E > A1 - 2δ - F1 - (L + L1) × K1
```

| Обозначение | Значение |
| --- | --- |
| D | Минимальный сквозной диаметр детали |
| F | Меньшее отклонение сквозного диаметра |
| E | Сквозной диаметр с учётом допуска |
| A1 | Наружный размер сечения трубы |
| δ | Толщина стенки трубы |
| F1 | Отклонение толщины стенки |
| L, L1, K1 | Длина детали, её большее отклонение и кривизна заготовки |

Если стенка не подбирается, перейти к следующему наружному размеру. Для перебора предусмотрено ограничение:

```text
A1 - 2δ > A
```

Смысл этого ограничения и порядок остановки перебора требуют уточнения. Если подходящая труба не найдена, рассмотреть круглый прокат с подбором по пункту 2.5.

<a id="p-2-7"></a>

### 2.7. Подбор листового проката

Определить минимальный габаритный размер детали `A`, принимаемый за толщину, и его большее отклонение `B`:

```text
C = A + B
```

Перебрать минимальную толщину заготовки `A1` по условию:

```text
C > A1 + B1 - (L + L1) × K1
```

Здесь `B1` обозначает минимальное отклонение толщины заготовки, `L` соответствует большему габаритному размеру детали, `L1` обозначает его большее отклонение, `K1` характеризует кривизну заготовки.

Направление неравенства для толщины необходимо проверить. После выбора толщины подобрать минимальные ширину и длину заготовки по оставшимся габаритам детали.

<a id="stage-3"></a>

## Этап 3. Инженерные расчёты

Результат этапа: карта операций с последовательными состояниями изделия, режимами, временем и стоимостью обработки.

Подробные требования, алгоритмы и архитектура расчётного сервиса приведены в [плане инженерных расчётов](16-ПЛАН_ИНЖЕНЕРНЫХ_РАСЧЁТОВ_2026-10-27.md).

<a id="p-3-1"></a>

### 3.1. Подготовка входных данных

- Техническое задание и требования чертежа.
- Описание поверхностей, размеры и привязки между собой и к базам.
- Материал и плотность.
- Форма, размеры и масса заготовки.
- Сведения о станках.

```text
Масса заготовки = Объём заготовки × Плотность
```

Проверить полноту передачи описания поверхностей в расчёты. Определить минимальные сведения о станке для выбора операции; на первом этапе допустима оценка агентом по названию и типу с явными допущениями.

<a id="p-3-2"></a>

### 3.2. Карта операций и подбор оборудования

Подбирать станки по материалу, текущей массе и габаритам изделия. Учитывать изменение размеров после каждой операции.

На одном станке допускается несколько видов обработки: сверление, расточка, торцовка и другие совместимые работы.

Шероховатость и точность конечной детали учитывать при выборе стадий. Если станок пригоден для черновой обработки, но не обеспечивает конечное требование, предусмотреть финишную операцию на подходящем оборудовании. Правило учёта твёрдости уточнить.

<a id="p-3-3"></a>

### 3.3. Состояния изделия и объём обработки

Для каждой операции определить входное и выходное состояние: геометрию, габариты, объём и массу.

```text
V_обработки = V_до_операции - V_после_операции
```

Для отрезки отдельно учитывать рабочую заготовку, остаток прутка и пропил. Для электроэрозионной резки дополнительно определять площадь, для лазерной, газовой, плазменной и гидроабразивной резки определять длину режущего пути.

Использовать инженерную оценку достаточной точности с указанными допущениями. Следующий станок подбирать по состоянию после предыдущей операции.

<a id="p-3-4"></a>

### 3.4. Режимы и время обработки

Для каждого процесса определить режимы и производительность. Основные расчётные зависимости:

```text
t_машинное = V_обработки / Q_объёмная
t_машинное = S_обработки / Q_площадная
t_машинное = P_обработки / Q_линейная
t_общее = t_машинное + t_вспомогательное
```

Выбирать формулу по процессу и согласованным единицам. К машинному времени добавить относящиеся настройку, программирование и наладку. Разделять общую работу на партию и повторяемую работу на деталь.

Использовать [Walter Machining Calculator](https://mac.walter-tools.com/) как источник структуры расчётных операций и формул. Разработать переиспользуемое ядро на Go с собственным UI и доступом через HTTP, MCP и CLI по дополнению D13 подробного плана.

Режимы, производительность и вспомогательное время могут быть демонстрационными с возможностью замены реальными данными. Геометрия обработки должна иметь собственное расчётное основание.

<a id="p-3-5"></a>

### 3.5. Стоимость и итог маршрута

Взять часовую ставку выбранного станка и рассчитать стоимость операции:

```text
Стоимость операции = Общее время в часах × Стоимость часа станка
```

Для всех операций повторять подбор оборудования, определение состояния изделия, объёма работ, режима, времени и стоимости.

Конечный результат должен соответствовать форме и объёму детали, техническому заданию, допускам и требованиям к шероховатости. При оценке сохранять ограничения и нерешённые требования.

Демонстрационные значения ставок и других параметров должны быть отличимы от реальных. Политику стоимости материала, учёт остатков и состав дополнительных расходов определять явно.

<a id="p-3-6"></a>

### 3.6. Представление результата

Для каждой операции выводить материал, размеры, массу, обработанные поверхности, режимы, время и стоимость.

Пример последовательности записей:

| Стадия | Материал | Габариты | Масса |
| --- | --- | --- | --- |
| Заготовка | 12х18н10т | Ø75×6000 | 208 кг |
| Резка на пиле | 12х18н10т | Ø75×255 | 8,835 кг |
| Черновая токарная обработка | 12х18н10т | Ø75×250 | 8,662 кг |
| ТВЧ-закалка | 12х18н10т | Ø75×250 | 8,662 кг |
| Чистовая токарная обработка | 12х18н10т | Ø75×250 | 7,662 кг |
| Шлифовка | 12х18н10т | Ø75×250 | 7,2 кг |

Пример показывает структуру вывода. При подготовке расчётного примера проверить массы и применимость процессов к материалу. Постоянный внешний габарит не заменяет описание промежуточной формы детали.

<a id="stage-4"></a>

## Этап 4. Операторский контур

Результат этапа: оператор может проверить исходные данные, исправить их, согласовать заготовку и маршрут, выполнить пересчёт и получить итоговые документы.

<a id="p-4-1"></a>

### 4.1. Чертёж и данные на одном экране

Показывать исходный документ рядом с распознанными данными. Обеспечить удобный переход от записи к соответствующему месту чертежа.

<a id="p-4-2"></a>

### 4.2. Происхождение значений и замечания

Понятным языком показывать источник значения, степень уверенности и выявленные противоречия. Для каждого замечания объяснять предмет проверки и необходимое действие.

<a id="p-4-3"></a>

### 4.3. Правки, причины изменений и пересчёт

- Предусмотреть единое окно корректировок основных параметров, включая размеры и материал, в табличном виде рядом с чертежом.
- Выводить интерактивный список замечаний для последовательного разрешения или подтверждения.
- Сохранять причину каждой правки. Предусмотреть выбор из списка, например «ошибка распознавания» или «изменение по требованию технолога».
- Во время редактирования не запускать автоматический пересчёт стоимости.
- После разрешения конфликтов запускать пересчёт единой командой «Применить изменения и пересчитать».

<a id="p-4-4"></a>

### 4.4. Выбор заготовки, оборудования и маршрута

Предусмотреть подтверждение и ручное изменение предложенных решений:

1. Выбор формы и размера заготовки из доступного перечня НСИ с получением относящихся стандартных припусков. Основание припуска должно быть видно.
2. Назначение оборудования из справочника реально имеющегося парка без свободного ввода стороннего станка.
3. Перестановку, удаление и добавление операций или переходов в укрупнённом маршруте, включая контрольные операции.
4. Проверку данных перед построением карты и принятие карты перед проработкой операций двумя отдельными решениями оператора.

<a id="p-4-5"></a>

### 4.5. Версии и история действий

Раздельно хранить исходный результат распознавания и данные с ручными правками. Сохранять версии и журнал изменений: прежнее значение, новое значение, автор и время изменения.

История должна позволять проверить действия оператора и причины изменения расчёта без утраты исходного чтения.

<a id="p-4-6"></a>

### 4.6. Состояние длительной обработки

Отображать фактическое состояние длительных процессов. Показывать выполняемую работу, доступный результат и причину ожидания или остановки без фиктивного прогресса.

<a id="p-4-7"></a>

### 4.7. Экспорт согласованного результата

Обеспечить экспорт согласованных данных, включая предварительную смету. Документ сметы формировать в готовом для использования виде на основе утверждённых и пересчитанных данных.

<a id="stage-5"></a>

## Этап 5. Тестирование

Результат этапа: проверены полный сценарий, расчёты, ограничения оборудования и ручные изменения; измерены показатели качества и описаны ограничения первой версии.

<a id="p-5-1"></a>

### 5.1. Контрольные документы и полный сценарий

Подготовить набор одностраничных чертежей с известными параметрами, представляющих тела вращения и плоские/листовые детали.

Для каждого документа пройти единый пользовательский сценарий от загрузки до паспорта и сметы. Сравнить результат с ручной проверкой.

Измерить общее время работы технолога вручную и время работы с системой, включая автоматическую обработку и проверку оператором.

Вести реестр ошибок: знаки диаметра, похожие цифры, марки материалов и другие повторяющиеся случаи.

<a id="p-5-2"></a>

### 5.2. Расчёты и ограничения оборудования

Проверить массу заготовки, расход материала и стоимость операций по тарифам справочников.

Проверить выявление несовместимости с оборудованием, включая превышение допустимых габаритов и другие заданные ограничения.

<a id="p-5-3"></a>

### 5.3. Правки, версии и повторный расчёт

Проверить изменение материала и размера заготовки, применение правок и последующий пересчёт сметы через команду этапа 4.3.

Проверить сохранение исходного распознавания и всех версий оператора. Убедиться, что смета относится к выбранной версии данных.

<a id="p-5-4"></a>

### 5.4. Численные показатели качества

После измерений определить:

- Долю корректно извлечённых размеров и марок материалов. Рассматриваемый ориентир: не менее 85% на контрольном наборе; окончательный порог установить по результатам измерений.
- Допустимое расхождение предварительной сметы с ручной эталонной сметой предприятия.

Для каждого показателя зафиксировать состав выборки, способ подсчёта и условия сравнения.

<a id="p-5-5"></a>

### 5.5. Проверки после исправлений

После исправления ошибок повторять относящиеся проверки и контролировать отсутствие ухудшений ранее полученных результатов.

<a id="p-5-6"></a>

### 5.6. Отчёт об ограничениях первой версии

Подготовить итоговый отчёт о качестве, известных ограничениях и условиях дальнейшего расширения системы.

<a id="stage-6"></a>

## Этап 6. Оптимизация на основе тестирования

Результат этапа: выявлены основные задержки, трудозатраты и расходы; улучшения выбраны по измеренным данным.

<a id="p-6-1"></a>

### 6.1. Задержки, производительность и нагрузка

1. Измерить время каждого этапа от загрузки чертежа до готовности сметы.
2. Определить критический путь и этапы с наибольшими задержками, включая внешние обращения и обработку графики.
3. Оценить пиковую нагрузку на процессор, оперативную память и видеопамять при одновременной работе нескольких операторов.

<a id="p-6-2"></a>

### 6.2. Трудозатраты оператора и качество распознавания

1. Собрать статистику наиболее часто исправляемых полей. Например, высокая доля правок диаметра должна стать предметом анализа причин и выбора доработок распознавания.
2. Измерить время, затрачиваемое оператором на отдельные шаги и принятие решений перед согласованием сметы.
3. Систематизировать причины правок для выявления устойчивых дефектов, включая ошибки чтения отдельных шрифтов. По результатам определить меры улучшения и необходимость дообучения.

<a id="p-6-3"></a>

### 6.3. Ресурсоёмкость и стоимость инфраструктуры

1. Рассчитать стоимость обработки одного успешно завершённого чертежа с учётом модели, расхода токенов и других используемых ресурсов.
2. Сравнить варианты по качеству, времени и стоимости на сопоставимых условиях.
3. Проверить наличие дублирующих и зацикленных обращений к моделям, расчётному ядру и базе данных, особенно после ручных правок.
