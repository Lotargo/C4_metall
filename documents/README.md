# Документы плана реализации

Публичные документы раздела находятся в `documents/implementation/`. Все файлы
`**/*.md` из этой папки, включая вложенные каталоги, автоматически попадают
в меню и получают страницы `/implementation/<путь-файла-без-md>/`.
Добавлять импорт или редактировать список навигации не нужно.

Весь каталог предназначен для публикации. Черновики, секреты и внутренние
материалы храните за его пределами.

## Добавление документа

Поместите готовый `.md` в `documents/implementation/`. Переписывать его
структуру, добавлять специальный заголовок или метаданные не требуется.
В разделе показываются только добавленные документы, без вводных страниц,
примеров и инструкций по оформлению.

При необходимости название в меню и порядок можно задать метаданными:

```yaml
---
title: Название в меню
description: Краткое описание
order: 10
---
```

Метаданные необязательны. Без `title` используется первый заголовок `#`, а при
его отсутствии имя файла. Сначала документы сортируются по `order` (по умолчанию
100), затем по пути с учётом чисел. В `/implementation/` открывается первый
документ. У каждого документа также есть собственный адрес.

В режиме `npm run dev` содержимое обновляется при сохранении. Для статического
сайта новый документ появится после `npm run build` и публикации сборки.

## Редактирование на сайте

Обычные страницы раздела позволяют вводить текст по клику и оформлять выделение
через ПКМ. Кнопки «Назад» / «Вперёд», Ctrl+Z / Ctrl+Y отменяют и повторяют до
20 действий текущего открытия. Форматирование также доступно через Shift+F10.

Все посетители могут редактировать без регистрации и окна входа. Firebase
создаёт анонимную сессию в фоне, затем редактор автоматически сохраняет полный
JSON документа в Firestore. Другие посетители получают сохранённые изменения
без перезагрузки. Схема работает и со статической сборкой, включая GitHub Pages.
Индекс раздела и собственная страница документа используют одну общую запись.

Исходный `.md` не перезаписывается. Обновление `.md` после веб-правок требует
сознательного согласования с сохранённым JSON, автоматического слияния нет.
При потере связи несохранённые правки остаются в браузере. Проверка etag не даёт
устаревшему окну молча перезаписать чужие правки: при конфликте можно скачать
свою копию и открыть общий документ. Посимвольное слияние одновременных правок
не реализовано. История 20 действий относится к текущему локальному открытию;
загрузка чужого сохранённого документа очищает её.

Локальные сохранения `.local/implementation/` остаются отдельно.
При отключённой конфигурации Firebase редактор использует прежний
локальный API, а без API сохраняет правки только в браузере.

## Поддерживаемое оформление

- Обычный Markdown, таблицы GFM, списки с отметками, цитаты, код с подсветкой.
- Заголовки `##` и `###` автоматически образуют оглавление.
- Ссылки `[название](соседний.md#раздел)` преобразуются в адреса страниц.
  Поддерживаются вложенные пути, пробелы и кириллица. Ссылки на локальные файлы,
  не включённые в раздел, отображаются как текст: исходный путь доступен
  в подсказке. Переносить зависимости документа или переписывать его не требуется.
- Для общих изображений и файлов используйте `public/` и ссылки от корня,
  например `![Описание](/images/diagram.png)`. Базовый путь GitHub Pages
  добавляется при сборке. Локальные изображения рядом с `.md` обрабатывает Astro.
- Схемы: блок кода с языком `mermaid`. Исходный текст остаётся доступным под
  схемой; ошибка одной схемы не мешает читать остальной документ.
- LaTeX: `$a^2$` внутри строки, `$$` на отдельных строках для блочной формулы.
  Рендеринг выполняет KaTeX при сборке, включая MathML для средств доступности.
  Поддерживается математический синтаксис KaTeX, не компиляция целого TeX-файла.

Скрипты Markdown исполнять не требуется. Используйте Markdown для содержания,
не вставляйте исполняемые HTML-скрипты. Mermaid работает в режиме `strict`,
LaTeX с `trust: false`. Зависимости и шрифты включены в сборку без CDN.
