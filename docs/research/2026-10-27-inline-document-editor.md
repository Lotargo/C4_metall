# Редактирование плана реализации на странице

Дата: 2026-10-27. Статус: исследование и предложение, до реализации.

Текущее состояние после реализации и удаления пробы:
[общий редактор Firebase](../qa/2026-10-27-editor-firebase.md).

После обсуждения реализована отдельная локальная проба Tiptap на копии плана.
Результаты и ограничения: [проверка редактора](../qa/2026-10-27-editor-preview.md).
Далее сохранена исходная запись исследования.

## Требования

- Нажатие на текст сразу ставит курсор и позволяет вводить текст, пробелы,
  переносы строк, удалять и вставлять содержимое. Кнопка «Редактировать» не нужна.
- Выделение и ПКМ открывают меню форматирования: полужирный, курсив,
  подчёркивание, цвет текста, цвет выделения, заголовок и подзаголовок.
- Пользователь редактирует оформленный документ, без открытия исходного Markdown.
- Правки сохраняются в общем документе на сайте и видны с других устройств
  и другим читателям. Это прямо выбрано пользователем в этом обсуждении.
- Существующие таблицы, формулы, Mermaid-схемы, ссылки и оформление остаются
  частью документа. Ограничения импорта необходимо проверить до внедрения.

## Предлагаемый подход

Tiptap в текущем Astro, без добавления React. Сохраняем ширину документа,
типографику, темы и левую навигацию; редактор работает в основной области текста.
ПКМ-меню представляет собой небольшой собственный UI над командами библиотеки.
Работу курсора, выделения, ввода, undo/redo и таблиц выполняет библиотека.

На телефоне и при работе с клавиатурой те же команды доступны через панель
выделения и сочетания клавиш. ПКМ не становится единственным способом доступа.
Предлагаемый основной доступ к форматированию на компьютере: ПКМ, как запросил
пользователь; автоматическую панель при выделении можно включить дополнительно.

### Хранение общего документа

Статическая сборка сама не может записать изменения обратно в репозиторий.
Предлагается отдельное общее API с БД; обе опубликованные копии сайта смогут
обращаться к одному хранилищу. Конкретный сервис пока не выбран.

- Чтение текущей версии и её номера через API.
- Авторизованные редакторы вводят текст сразу по клику; читатели видят тот же
  документ в режиме чтения. Это предлагаемая модель доступа.
- Автосохранение после короткой паузы; локальная аварийная копия в IndexedDB
  защищает ввод до подтверждения сервера. Общим источником остаётся сервер.
- Номер базовой версии передаётся при записи. Устаревшая запись отклоняется;
  изменения двух редакторов не перезаписывают друг друга молча.
- Каждая принятая версия сохраняется в истории. Восстановление создаёт новую
  версию, чтобы история не исчезала.
- Совместное редактирование с курсорами нескольких участников не входит
  автоматически в первую версию: при необходимости это отдельный этап.

Для веб-версии предлагается структурированный JSON редактора. Он сохраняет цвет,
подчёркивание и структуру без ограничений обычного Markdown. Markdown остаётся
форматом исходного импорта и контролируемого экспорта; нельзя объявлять сразу
два независимо изменяемых формата равноправными источниками истины.

Первоначальный Markdown сохраняется вместе с хешем источника. Новая версия
файла в репозитории не должна молча замещать правки сайта. Повторный импорт
требует сравнения версий. Служебные комментарии и явные якоря нужно сохранять
как метаданные или специальные узлы, проверив их обратный экспорт.

Цвет и подчёркивание не входят в базовый Markdown: для экспорта понадобятся
согласованные HTML-элементы либо расширенный синтаксис и поддержка в рендерере.
Преобразование через готовый HTML страницы и общий конвертер без проверки
сохранности содержимого не подходит.

### Поведение взаимодействий

| Действие или состояние | Предлагаемое поведение |
| --- | --- |
| Клик по тексту | Курсор появляется в месте клика, ввод доступен сразу после загрузки редактора. |
| Выделение и ПКМ | Меню появляется у выделения; открытие меню сохраняет выделение. Системное меню вне области редактора остаётся доступным. |
| Форматирование | Команда применяется к выделению; заголовок меняет тип содержащего его абзаца. Для смешанного выделения показывается смешанное состояние. |
| Escape | Закрывает меню и возвращает фокус в текст, не отменяет уже введённое. |
| Изменение заголовка | Оглавление обновляется; существующие целевые якоря сохраняются. |
| Ctrl+Z / Ctrl+Y | Отмена и повтор локальных операций средствами редактора; история серверных версий существует отдельно. |
| Сохранение | Показываются состояния «Сохраняется», «Сохранено» либо «Нет связи». «Сохранено» появляется только после подтверждения сервера. |
| Потеря сети | Ввод остаётся в локальной аварийной копии. Повторная запись сверяет версию сервера. |
| Чужая правка | Несохранённый ввод сохраняется; показывается конфликт с возможностью сравнить версии. Автоматического затирания нет. |
| Формула или схема | Формула и схема сохраняют структурированный исходник и показываются визуально; редактирование их внутреннего языка рассматривается отдельно от обычного текста. |

## Первый проверяемый этап

Перед изменением рабочей страницы сделать изолированную пробу Tiptap на копии
настоящего инженерного плана. Если сохранность Markdown окажется слишком
дорогой в поддержке, на той же копии проверить Milkdown.

Критерии выбора:

1. Ввод кириллицы, пробелов, абзацев; выделение мышью и клавиатурой; undo/redo.
2. Форматирование из ПКМ-меню, включая выделение через несколько фрагментов.
3. Таблицы, ссылки, формулы, Mermaid, комментарии и явные якоря проходят цикл
   импорта, изменения, сохранения, повторного открытия и экспорта без потерь.
4. Изменение текста и заголовков не ломает оглавление и переходы по ссылкам.
5. Светлая/тёмная тема, мобильный ввод и печать сохраняют читаемость.
6. Сохранённая версия видна во втором браузере. Старая версия при конкурирующей
   записи отклоняется с сохранением обоих вариантов.
7. Потеря сети и перезагрузка не теряют неподтверждённый ввод.

В рамках этого исследования исходники интерфейса, зависимости и публикация
не изменяются. Реализация и выбор конкретного хранилища следуют после обсуждения.
