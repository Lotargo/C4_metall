# Редактор на основных страницах плана реализации

Дата: 2026-10-27.

Эта запись фиксирует этап переноса редактора. Последующее подключение Firebase
и удаление пробы описаны в [актуальной проверке](2026-10-27-editor-firebase.md).

## Исправленная причина

Tiptap был подключён только к `/editor-preview/`. Основной компонент
`ImplementationDocument.astro`, используемый адресами `/implementation/` и
`/implementation/<документ>/`, оставался просмотрщиком. Возврат в него закономерно
показывал системное меню браузера вместо команд оформления.

Теперь основной компонент подключает общие `EditorControls.astro`,
`EditorMenu.astro`, `EditorRecovery.astro`, `document-editor.ts` и стили редактора.
Проверки `DEV`, отключающей редактор в сборке основных страниц, нет.
`/editor-preview/` перенаправляет в основной раздел. Прежние пробные данные
сохранены отдельно, в основной документ они автоматически не переносятся.

## Документы и данные

- Содержимое импортируется из настоящего Markdown выбранного документа через
  `src/editor/seed.mjs`; в основной план не добавляются тестовые формулы или фразы.
- Frontmatter остаётся метаданными. Документам без H1 добавляется тот же
  заголовок из метаданных или имени файла, который использовал просмотрщик.
- Относительные ссылки разрешаются по каталогу документов, включая вложенные
  папки и базовый путь GitHub Pages. Исходные адреса остаются в JSON.
- Для изображений рядом с Markdown используется карта ресурсов сборки;
  задачи GFM сохраняют состояния флажков. Формулы и Mermaid сохраняются
  отдельными структурированными узлами.
- `GET/PUT /api/implementation/document?id=...` выбирает документ только из
  разрешённого каталога. Произвольный путь запроса не читается.
- Каждый документ имеет независимый `current.json` в
  `.local/implementation/<sha256-id>/`. Раздел-индекс и собственный адрес
  документа используют один идентификатор и одно сохранённое содержимое.
- Веб-правки не перезаписывают исходный `.md`. Нумерации и архива новых версий
  нет; контрольная сумма защищает от устаревшей записи другого окна.
- Сохранены автосохранение, отмена/повтор 20 действий, Ctrl+Z / Ctrl+Y,
  SVG-кнопка печати, темы и оглавление. Подсказки над документом не возвращались.
- Оглавление и его подсветка работают с обновляемыми ссылками редактора.
  На мобильной ширине высота шапки измеряется, чтобы оглавление не перекрывало
  кнопки; ссылки навигации остаются доступны.

## Проверки

В Chrome на **обычном** `/implementation/`:

1. Область документа имеет `contenteditable=true`; ПКМ на выделенном заголовке
   открывает наше меню. Курсив применяется и отменяется Ctrl+Z.
2. В абзац временно добавлено `[OK]`; после автосохранения выполнен переход
   по выбранному документу в левом меню на его собственный адрес.
3. Внесённый текст остался, редактор и меню доступны. После удаления `[OK]`
   и автосохранения проверен возврат в `/implementation/`.
4. Исходные 14 таблиц, 59 ссылок, 1 Mermaid, 32 фрагмента служебного HTML и
   11 блоков кода совпадают с импортом по полному содержимому и атрибутам.
   В оригинале нет LaTeX; контрольные формулы остались в прежней пробной копии.

В отдельном in-app браузере:

- На ширине 390 px нет горизонтального переполнения. Верх оглавления совпадает
  с фактической высотой шапки; навигация не скрыта.
- На `astro preview`, где dev API отсутствует, основной маршрут также имеет
  редактор и ПКМ-меню. Локальная правка переживает перезагрузку, тестовая вставка
  затем удалена. Статус явно указывает сохранение в этом браузере.

`npm run test:editor`: 9/9. Дополнительные проверки покрывают отсутствие
тестовых вставок в основном документе, необязательность H1/frontmatter,
независимость двух документов, вложенные ссылки и оба базовых пути, сохранность
изображений, задач, формул и схем, отклонение запроса за пределами каталога.

Полное сравнение выявило ошибку прежнего HTTP-обработчика: `body += chunk`
декодировал каждый Buffer отдельно и мог повреждать UTF-8 на границе порций.
Теперь `readDocumentRequest` сначала собирает байты с ограничением размера,
а затем один раз декодирует и разбирает JSON. Регрессия проверена на порциях
по 1, 3 и 65536 байт, включая кириллицу и emoji.

В сохранённом основном документе исправлена одна повреждённая строка, в точности
сопоставленная с исходником; прочие данные не заменялись. До исправления сохранена
локальная копия для проверки в `outputs/.../before-transport-repair.json`.
После исправления и настоящего HTTP-сохранения совпадают не только защищаемые
структуры, но и все текстовые узлы документа. Исходный Markdown не менялся.

Проходят `npm run typecheck`, `npm run verify:evidence`, корневая сборка и
сборка с `/C4_metall/`. В обеих сборках проверены наличие редактора на индексе
и собственном адресе документа, одинаковый идентификатор и перенаправление
старого тестового адреса.

Материалы: `outputs/editor-main-2026-10-27/verification.json`, `main-context-menu.png`.

## Границы размещения

Общий файл сохранения работает через локальный dev API. Статические хостинги
GitHub Pages и текущая конфигурация Sites сами не принимают записи: при отсутствии
API редактор сохраняет черновик в браузере и сообщает именно это. Общий
интернет-сервис хранения и авторизация не подключены. Изменения ещё не опубликованы.

Существующие веб-правки имеют приоритет над новым импортом Markdown. Автоматическое
слияние последующих изменений исходного `.md` с уже сохранённым JSON не реализовано.

Источник metall-dev-2 не менялся и не запускался. Архитектурный снимок не обновлялся.
Коммит, push и публикация не выполнялись.
